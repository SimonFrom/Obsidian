
TURBO er et akronym for: 
**T**eknologi - **U**dviklerne - **R**esultatet - **B**rugerne - **O**mgivelserne

---

### 1. Analyser særlige mål og betingelser:
Fokuser på hvad der er særligt ved netop dette projekt og noter det ned i en tabel som denne:

| Mål og betingelser | Særlige styrker | Særlige svagheder | Mulige strategiske handlinger |
| ------------------ | --------------- | ----------------- | ----------------------------- |
| Teknologi          |                 |                   |                               |
| Udviklerne         |                 |                   |                               |
| Resultatet         |                 |                   |                               |
| Brugerne           |                 |                   |                               |
| Omgivelserne       |                 |                   |                               |
Tilføj gerne flere rækker hvis de er relevante for projektet.

---
### 2. Overvej strategiske handlinger:
For hver af de noterede **svagheder** skal man forsøge at lave forskellige handlinger, der kan kan hjælpe med at overvinde dem.
For **styrkerne** skal man noterer *hvordan* de kan bidrage til projektet.

Disse lister bør være omfattende og gennemarbejdede, hvilket kan betyde at man er nødt til at fravælge noget.

---
### 3. Afvej svagheder:
Kig grundigt på svaghederne. 
- Hvilke er de værste og mest ukendte?

Står man tilbage med mange store og ukendte, kan det være at man skal redefinere projektets størrelse eller scope.

---
### 4. Formulering af projektstrategi:
Efter overblikket er dannet skal man vælge den overordnede strategi for projektet.
Kig i modellen på de mulige strategiske handlinger for de største problemer
Se [[Strategi]] for kriterier til en god strategi.
Slutteligt formuleres en strategi så den opfylder de nævnte kriterier.

---

### Valg af procesmodel:

| Særlige betingelser                                            | Strategi                           | Procesmodel          |
| -------------------------------------------------------------- | ---------------------------------- | -------------------- |
| Høj usikkerhed                                                 | Eksprerimenter                     | Eksperimentel        |
| Høj kompleksitet                                               | Formalisering                      | Traditionel/Vandfald |
| Særligt vanskeligt                                             | Forenkling                         | Inkrementel          |
| Tidsbegrænsninger, organisatorisk<br>eller geografisk opdeling | Decentralisering                   | Parallel             |
| Tidsbegrænsninger eller økonomi                                | Justering af standardiseret system | Erhverelse           |
Denne tabel kan hjælpe en med at vælge en procesmodel.

#### Usikkerhed:
Der er høj grad af usikkerhed hvis der er store eller vigtige områder, hvor betingelserne eller målene ikke er kendt. Ny og uafprøvet teknologi f.eks.

#### [[Kompleksitet]]:
Her skal forstås hvor komplekst systemet eller projektet er. Det kan være at der er enormt mange brugere, scenerier eller situationer. Et lager system til en person er ikke voldsomt komplekst, men skal det bruges af 20 mand på 10 lokationer på samme tid og snakke sammen med lagerstatus, bliver det enormt komplekst.

#### Særligt vanskelige forhold.
Dette er en blanding af de to overstående.

#### Organisatorisk eller geografisk opdeling:
Hvis der er mulighed for at opdele projektet i afdelinger eller geografisk, kan nogle af vanskelighederne minimeres. Det kan dog også resultere i nye vanskeligheder! 

#### Tidsbegrænsninger eller økonomi:
Når tid eller penge er knappe ressourcer, bør det undersøges, om der allerede findes et  standardiseret system, der kunne erhverves og eventuelt tilpasses til behovene.



### Valg af metode:
Når procesmodellen er valgt kan man begynde at kigge på systemudviklings metoder. 

### Justering af procesmodel og systemudviklings metoden:
Det kan være nyttigt at justere PM og SUM med elementer fra andre modeller for at følge strategien. Har man for eksempel valgt vandfald, kan man prøve eksperimentere i analyse fasen for eventuelt at kunne fjerne nogle svagheder.
Den valgte SUM vil give forskellige teknikker til udvikling, her bør man overveje om de passer til strategien eller om de skal tilpasses. 

### Planlægning:
Nu kan planlægningen af systemet begynde.
1. Hvilke ting skal udføres og hvornår?
2. Af hvem?
3. Hvilke resultater forventes for overstående?
